# FileHub 0.2.2

0.2.2 is a small compatibility patch focused on Android photo sync and update visibility.

## Directory creation is now idempotent

If a client calls `mkdir` for a directory that already exists, FileHub now returns `409 Conflict` instead of `500 Internal Server Error`. This is safe for Android clients to ignore while ensuring a directory exists.

The fix also means:

- A repeated `mkdir` does not increase the entry count.
- A file with the same name returns `400` instead of being mistaken for a directory.
- A missing parent returns a clear client error.
- Permission failures stay `403`.
- Remote mounts use the same behavior as local directories.

## Update checks

- The server checks GitHub hourly in the background.
- When a newer version appears, connected clients receive an `updates.changed` SSE event.
- The sidebar then shows “update available”.
- Once a new version is found, the hourly check stops; a restart or manual check starts it again.

## Upgrade

Migrations are unchanged. Existing 0.2.1 data can be upgraded in place.

Full changelog: https://github.com/Llesue/filehub/compare/v0.2.1...v0.2.2

Demo: https://filehub.ihtom.com (demo / filehub2026)

# FileHub 0.2.2

0.2.2 是一个小的兼容性修复版本，主要处理 Android 相册同步和更新提示。

## 新建目录支持重复调用

客户端对已存在的目录再次调用 `mkdir` 时，FileHub 现在返回 `409 Conflict`，而不是 `500 Internal Server Error`。Android 客户端可以安全地忽略 409，继续上传。

同时修复了：

- 重复 `mkdir` 不再增加 entry 计数
- 同名文件返回 `400`，不会被误认为目录
- 父目录不存在返回明确的客户端错误
- 权限不足仍然是 `403`
- 远程挂载和本地目录使用相同语义

## 更新检查

- 服务端每小时在后台检查 GitHub
- 发现新版本后通过 SSE `updates.changed` 通知已连接的前端
- 侧栏显示“有新版本”
- 发现新版本后停止每小时轮询；重启或手动检查会重新开始

## 升级

数据库迁移没有变化，0.2.1 的数据可以直接升级。

完整更新记录：https://github.com/Llesue/filehub/compare/v0.2.1...v0.2.2
