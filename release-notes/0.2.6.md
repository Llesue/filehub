# FileHub 0.2.6

0.2.6 keeps FileHub responsive while large directories sync, adds content-hash sync for clients, and makes account and share lifecycles safer.

## Highlights

- Large syncs no longer freeze the instance: directory changes settle before indexing, scans run on a time budget, and interactive requests keep priority.
- Quick and full scans resume where they stopped, so one huge tree cannot starve the rest of the index.
- Admins can mark paths `normal`, `background`, `on_demand` or `ignore` through the index policy API, and search visibility follows the policy.
- A watchdog cancels index and directory-size jobs that stay queued or stop reporting progress.
- Index writes are serialized and background IO is capped, so large scans no longer produce `database is locked` spikes.
- Search hides a directory while it is being rebuilt, so half-finished results never appear.
- SHA-256 is available for one file or a batch, with a persistent cache keyed by size and mtime.
- Uploads can carry a client SHA-256 and are verified before an overwrite touches the existing file.
- FileHub advertises hash capabilities so Android 0.1.5 can use them while older clients keep working unchanged.
- Admin password resets now issue a temporary password and force a change before the user can do anything else.
- Resetting a password revokes the user's sessions and API tokens immediately.
- Permanent passwords must be 8–128 characters, while login still accepts existing shorter passwords.
- Expired shares become stopped automatically, and open share pages close as soon as they expire.
- Lists and properties can return cached hashes without triggering new disk reads.
- `/api/v1/index/metrics` gives admins change-gate, scan, queue and database lock numbers.

## Upgrade

Database migrations 0038–0042 run automatically. Back up the database before upgrading; downgrading to 0.2.5 is not a supported path. Existing users keep their passwords, existing sessions and API tokens stay valid, and shares that already expired are marked stopped on the first sweep.

# FileHub 0.2.6

0.2.6 让 FileHub 在大目录同步时保持响应，加入客户端内容哈希，并让账号和分享的生命周期更安全。

## 亮点

- 大目录同步不再拖垮整个实例：目录变化稳定后才索引，扫描带时间预算，交互请求始终优先。
- 快速扫描和全量扫描从断点继续，一棵巨大的目录树不会再把其余索引饿死。
- 管理员可以通过索引策略 API 把路径设为 `normal`、`background`、`on_demand` 或 `ignore`，搜索可见性跟着策略走。
- 看门狗会取消长期排队或停止上报进度的索引和目录大小任务。
- 索引写入串行化并限制后台 IO，大扫描不再制造 `database is locked` 峰值。
- 搜索会隐藏正在重建的目录，半成品结果不会出现。
- 单个文件或批量查询都能拿到 SHA-256，缓存按大小和 mtime 失效。
- 上传可以携带客户端 SHA-256，覆盖前先校验，不会先删掉旧文件。
- FileHub 会声明哈希能力，Android 0.1.5 可以直接使用，旧客户端行为不变。
- 管理员重置密码改为临时密码，用户必须先完成强制改密才能继续操作。
- 重置密码会立即撤销该用户的 session 和 API token。
- 永久密码要求 8–128 位，但登录仍接受已有短密码。
- 分享过期后自动进入停止状态，已打开的分享页会立即关闭。
- 列表和属性接口可以直接返回缓存哈希，不再触发新的磁盘读取。
- `/api/v1/index/metrics` 让管理员看到变化门控、扫描、队列和数据库锁数据。

## 升级

数据库迁移 0038–0042 会自动执行。升级前请备份数据库；降级回 0.2.5 不是受支持的路径。现有用户密码、session 和 API token 保持有效，已经过期的分享会在第一次扫描时标记为已停止。
